Why Arise Server

      
One box. One login. Nothing silent.

      
Windows Server does this for a licence fee and a bigger machine. A home-server OS does the apps but not the directory. Arise Server is the narrow thing the church actually needs, wired together from boot: the directory the Macs bind to, the shares, the automator, the backups, the Synology and the apps, all reporting to one page in the church's own look.

      

        
01
Sign in once
Every Mac, the Windows PC and the Synology take the same account. New staff member: one command, one password.

        
02
Files on the server
Home folders and shares live on the box and the NAS, not on whichever laptop someone took home.

        
03
Runs the automator
The 2:05 AM YouTube job runs on the server, on a timer, with its report on the dashboard by breakfast.

        
04
Backed up, and says so
Every job writes a row, done or failed. A missing NAS, an expired token, a full disk: the Overview says it in red.

      

    

  


  

    

      
What it does

      
Everything the church asked for. Nothing it did not.

      

        
Active Directory for the Macs
A Samba AD domain controller, realm AD.ARISECENLA.CHURCH. Macs bind with Apple's own Directory Utility, log in with mobile accounts, and keep Desktop and Documents on the server. Kerberos, LDAP and DNS included.

        
Home folders and shares
One private folder per person, Mac-friendly (vfs fruit), plus shared folders by group. Moving an old Mac's data in is one script with a manifest, and nothing is ever deleted by it.

        
The automator, on a timer
arise_daily.py runs at 02:05 Central from systemd, five minutes after the quota resets. The hold list, the worklist, the quota ledger and every report are on the dashboard. Preview tonight with one click.

        
Backups that report
restic snapshots to the Synology at 03:00: the automator, homes, shares, app data, the server config, and a mirror of every GitHub repo. Keep 14 daily, 8 weekly, 12 monthly. Every run writes a row.

        
The Synology, joined
The NAS joins the domain, holds the bulk files on four drives, is the backup target, and ships an off-site copy with Hyper Backup. The dashboard shows mount state, free space and DSM health.

        
A small app store
Docker Compose templates for what a church uses: File Browser, Uptime Kuma, Syncthing, Vaultwarden. Install, update, logs, remove, with the data folder always kept.

        
A desktop, not a dashboard
A menu bar, windows you drag, a floating dock, a launchpad with fifteen apps: Overview, Directory, Files, Backups, Automator, Sermons, Bible, Apps, Remote, Campuses, Terminal, Synology, Services, Logs, Settings. Works on a phone.

        
Reach it from anywhere
Built for a locked closet and three sites. Key-only SSH, a VPN (Tailscale, or self-hosted WireGuard), Guacamole remote desktop to any church computer from a browser tab, a Terminal app, HTTPS with the server's own CA. Pineville, Alexandria and the Apostolic Hub on one server.

Profiles

      
Two ways to run it. One is the real thing.

      

        

          Recommended
          
server
Ubuntu Server 24.04 LTS on the old PC.

          
  • Active Directory domain controller
  • Home folders, shares, Mac binding
  • Automator, backups, GitHub mirror on timers
  • Docker apps, Synology mount
  • Dashboard + arisectl

          
Needs: 2 cores, 4 GB RAM (8 GB with apps), a 64 GB+ SSD, wired Ethernet, on 24/7. Wipes Windows.

          Install path A
        

        

          Keep Windows
          
windows
Windows 10/11 stays. Four scheduled tasks and the dashboard.

          
  • Dashboard + arisectl
  • Automator at 02:05, backups at 03:00, mirror at 04:00
  • Windows file sharing, local accounts
  • No domain controller
  • No Mac domain login

          
A Windows 10/11 PC cannot be an Active Directory domain controller. That needs the server profile.

          Install path B
        

      

    

  


  

    

      
Install

      
From an old PC to the church server.

      
Send the specs first (docs/HARDWARE.md has the checklist). Then pick a path. Every command below is real and in INSTALL.md.

      

        

          
          
          
        

        


# 1. Install Ubuntu Server 24.04 LTS from a USB stick (installer/MAKE-USB.md)
# 2. On the new system:
sudo apt install -y git
git clone https://github.com/Rehchu/Church-server-OS-.git
cd Church-server-OS-
sudo bash installer/install.sh --admin-pass 'YourDomainAdminPassword'
# 3. First boot, in this order:
sudo arisectl admin set-password          # the dashboard login
# copy token.json + client_secret.json into /srv/arise/automator/ARISE_YouTube_Updater/
sudo nano /etc/arise/secrets/restic-password   # and write it on paper
sudo arisectl nas mount
sudo arisectl doctor

        

        


# PowerShell, as Administrator
git clone https://github.com/Rehchu/Church-server-OS-.git C:\Arise\app
Set-ExecutionPolicy -Scope Process Bypass
C:\Arise\app\installer\install.ps1
# Dashboard at http://localhost:4147 . Four scheduled tasks: Arise Web, Automator 02:05, Backup 03:00, Mirror 04:00.
# No domain controller on Windows - the Macs keep local accounts.

        

        


# Put installer/autoinstall.yaml on the Ubuntu USB stick (installer/MAKE-USB.md),
# boot the PC from it, walk away. It installs Ubuntu, clones this repo and runs
# install.sh --no-start. Then log in and finish path A from step 3.

        

      

    

  


  

    

      
Cookbook

      
Look how short it is.

      


# People
sudo arisectl user add jsmith --display "J Smith" --groups Staff
sudo arisectl user passwd jsmith
arisectl user list

# A Mac joins the domain (run on the Mac)
sudo ./mac/bind-mac.sh --computer-name MEDIA-MAC
sudo ./mac/migrate-mac-user.sh --from oldlocal --to jsmith

# Files
sudo arisectl share add graphics /srv/arise/shares/graphics --group Media


# Backups
arisectl backup status
sudo arisectl backup run homes
sudo arisectl backup restore latest --tag homes \
  --path /srv/arise/homes/jsmith/Documents --target /srv/arise/restore

# The automator
arisectl automator status
sudo arisectl automator preview

# Apps and the NAS
sudo arisectl app deploy uptime-kuma
arisectl nas status
sudo arisectl doctor

Support

      
Stuck? Start with doctor.

      

        
arisectl doctor
Checks the config, the password, Samba, DNS, the automator folder and its two credential files, restic and its password, the NAS mount, Docker, every timer and the clock, and prints what to fix in order.

        
The docs
INSTALL.md · DIRECTORY · MAC-MIGRATION · SYNOLOGY · BACKUPS · AUTOMATOR · HARDWARE

        
Issues
Something wrong in the code or the docs: open an issue with the output of arisectl doctor and the journal lines that mention it.
