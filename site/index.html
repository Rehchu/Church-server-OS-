Arise Church · Pineville, LA · v0.8.0 “Exodus”

The church server
built for the people
who run it on Sundays.

Arise Server turns an old PC into the church's own Active Directory, with no Microsoft licence: it makes and removes the accounts on every church Mac, and staff just sign in and work while their Desktop and Documents sync to the server. It also runs the nightly YouTube automator, backs up to the Synology and says when that fails, and keeps home folders and shares and an app store. At the closet monitor there is a desktop for the four admins, with Firefox. One box. One login. Nothing silent.

Why Arise Server

      
One box. One login. Nothing silent.

      
Windows Server does this for a licence fee and a bigger machine. A home-server OS does the apps but not the directory. Arise Server is the narrow thing the church actually needs, wired together from boot: the directory that runs the church Macs, the sync, the shares, the automator, the backups, the Synology and the apps, all reporting to one page in the church's own look. Staff and volunteers never see it: they use their Macs as normal.

      

        
01
Sign in once
A new staff member is one form. Their face appears on every church Mac's login window within minutes, and the same first.last password works everywhere.

        
02
Files on the server
Desktop and Documents sync to each person's server home through Nextcloud. When the same file changes in two places, the newest wins and the older copy goes to the Trash. Nothing lives only on the laptop someone took home.

        
03
Runs the automator
The 2:05 AM YouTube job runs on the server, on a timer, with its report on the dashboard by breakfast.

        
04
Backed up, and says so
Every job writes a row, done or failed. A missing NAS, an expired token, a full disk: the Overview says it in red.

      

    

  


  

    

      
What it does

      
Everything the church asked for. Nothing it did not.

      

        
The church's own Active Directory
A Samba AD domain controller, realm AD.ARISECENLA.COM (NetBIOS ARISE), with Kerberos, LDAP and DNS. Free, on the church's own box. Logins are first.last; email addresses are first.last@ad.arisecenla.com.

        
Every church Mac, managed
A small helper, enrolled with one Terminal line, makes and removes the domain accounts on church Macs only. Personal Macs are never touched. Accounts already on a Mac wait for an admin to choose Convert, Link or Leave alone. Before a profile is removed, the server confirms it holds every file, and a disk image is kept anyway.

        
The rest of the Mac's care
The helper also handles:
  • a hidden ariseadmin account whose password changes every 30 days, with a copy kept on the server
  • FileVault, with its recovery key kept on the server
  • printers, the church bookmarks and the church certificate
  • security updates overnight
  • Tailscale for off-site use
Retire takes a Mac out of use properly. Cut off handles a lost one.

        
Sync that just works
Nextcloud at cloud.ad.arisecenla.com keeps everyone's Desktop and Documents in step with their server home. Church, department and Pastors folders appear in Finder's sidebar. Phones use the Nextcloud app. A conflict keeps the newest copy and sends the older one to the Trash.

        
Folders and shares
A 50 GB home folder per person, plus:
  • a Church folder everyone writes
  • a folder per department
  • a Pastors folder for the two pastors only
  • Shared with me
Every share has a 30-day Trash, and Share with… works from the Finder.

        
The automator, and its archive
The 02:05 YouTube job runs on a timer as Bradly's own account. The PC stays the runner until he switches it. The Automator app lists every video, searches the transcripts (thumbnails, YouTube and Studio links, chapters, songs) and has a searchable song list. Lyrics imported from Proclaim or SongSelect are searchable and never quoted into a title.

        
Backups that report
restic snapshots to the Synology at 03:00: the automator, homes, shares, app data, the server config and a mirror of every GitHub repo. It keeps 30 daily, 12 weekly and 24 monthly. Every run writes a row, and a restore drill runs monthly.

        
The closet desktop
The four admins (Bradly, Kristina and the two pastors) use the OS on the closet monitor. It is a macOS-style desktop with 35 apps, two-step sign-in and an audit log. Each admin gets their own Firefox profile, a full browser with uBlock Origin, Google search and saved passwords.

        
A small app store
27 Docker Compose templates the church can use, from Uptime Kuma and Vaultwarden to Jellyfin, Immich and Nextcloud. You can install, update, view logs and remove, and an app's data folder is always kept.

        
Private, and reachable
Nothing on the box is reachable from the internet. Off-site Macs, phones and the Alexandria campus come in through Tailscale. SSH takes keys only, HTTPS uses the church's own certificate, and Guacamole reaches any church computer. Someone leaving gets 30 days before their account is disabled, and their files go to whoever takes over.

Profiles

      
Two ways to run it. One is the real thing.

      

        

          Recommended
          
server
Ubuntu Server 24.04 LTS on the old PC.

          
  • Active Directory domain controller
  • The Mac helper, home folders, shares, Nextcloud sync
  • Automator, backups, GitHub mirror on timers
  • Docker apps, Synology mount
  • Dashboard + arisectl

          
Needs: 2 cores, 4 GB RAM (8 GB with apps), a 64 GB+ SSD, wired Ethernet, on 24/7. Wipes Windows.

          Install path A
        

        

          Keep Windows
          
windows
Windows 10/11 stays. Four scheduled tasks and the dashboard.

          
  • Dashboard + arisectl
  • Automator at 02:05, backups at 03:00, mirror at 04:00
  • Windows file sharing, local accounts
  • No domain controller
  • No Mac domain login, no Mac helper, no Nextcloud sync

          
A Windows 10/11 PC cannot be an Active Directory domain controller. That needs the server profile.

Install

      
From an old PC to the church server.

      
Send the specs first (docs/HARDWARE.md has the checklist). Then pick a path. Every command below is real and in INSTALL.md.

      

        

          
          
          
        

        


# 1. Install Ubuntu Server 24.04 LTS from a USB stick (installer/MAKE-USB.md)
# 2. On the new system:
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/Rehchu/Church-server-OS-.git /opt/arise
sudo bash /opt/arise/installer/install.sh --kiosk --with-tailscale
#    (run it from your own account: it becomes the owner. Or pass --owner NAME.)
# 3. Then, in the order the installer prints:
sudo arisectl admin set-password          # the dashboard login
sudo arisectl automator setup             # after the read-only deploy key is on GitHub
sudo arisectl automator signin            # once; the PC stays the runner until you switch
sudo arisectl nas mount
sudo arisectl doctor

        

        


# PowerShell, as Administrator
git clone https://github.com/Rehchu/Church-server-OS-.git C:\Arise\app
Set-ExecutionPolicy -Scope Process Bypass
C:\Arise\app\installer\install.ps1
# Dashboard at http://localhost:4147 . Four scheduled tasks: Arise Web, Automator 02:05, Backup 03:00, Mirror 04:00.
# No domain controller on Windows - the Macs keep local accounts.

        

        


# Put installer/autoinstall.yaml on the Ubuntu USB stick (installer/MAKE-USB.md),
# boot the PC from it, walk away. It installs Ubuntu, clones this repo and runs
# install.sh --no-start. Then log in and finish path A from step 3.

        

      

    

  


  

    

      
Cookbook

      
Look how short it is.

      


# People
sudo arisectl user add jane.smith --display "Jane Smith" --groups Staff
sudo arisectl offboard mark jane.smith --to office
arisectl user list

# A church Mac: Macs app → Enrol a Mac → paste the one line
# into the Mac's Terminal. Accounts follow by themselves.
arisectl computer list

# Files
sudo arisectl share add graphics /srv/arise/shares/graphics --group Media
arisectl trash list
arisectl cloud conflicts


# Backups
arisectl backup status
sudo arisectl backup run homes
sudo arisectl backup restore latest --tag homes \
  --path /srv/arise/homes/jane.smith/Documents --target /srv/arise/restore

# The automator
arisectl automator status
sudo arisectl automator preview

# Apps and the NAS
sudo arisectl app deploy uptime-kuma
arisectl nas status
sudo arisectl doctor

Support

      
Stuck? Start with doctor.

      

        
arisectl doctor
Checks the config, the password, Samba, DNS, the automator and its sign-in, restic and its password, the NAS mount, Docker, every timer and the clock, and prints what to fix in order.

        
The docs
INSTALL.md · DIRECTORY · MACS · SYNC · BROWSER · SYNOLOGY · BACKUPS · AUTOMATOR · HARDWARE

        
Issues
Something wrong in the code or the docs: open an issue with the output of arisectl doctor and the journal lines that mention it.
